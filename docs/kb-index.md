# 知识库索引（网络/数据面）

按「现象 → 去哪一节」组织。所有条目都在 `docs/pitfalls.md`，桌面版另有专文。
版本层面的变更一览见 [`../CHANGELOG.md`](../CHANGELOG.md)；早期材料归档在 `docs/archive/`。

## 一、先看这三条判据

| 现象 | 先查什么 | 结论怎么读 |
|---|---|---|
| 速度慢 | 日志 `[diag] WARP 上游 1 流/4 流` | 两档都低 = 上游限速；单流低四流高 = 窗口/拥塞控制 |
| 连不上（节点） | 日志 `[vpn] establish …` | `Cannot set address` = 系统拒绝 tun 地址；握手失败 = 节点/网络 |
| 节点测出来有速度但连上没速度 | `[vpn] 出口实测速度` | 那只是 512 KB 短测（含慢启动），≠ 最终速度 |

## 三、改数据面代码前的检查清单

1. 先量上游（`[diag]` 两档），再动参数；
2. 改缓冲前确认自适应开关的真实状态 —— gVisor `Disabled` 时 `Max` 完全不生效；
3. 任何「一次只处理一个包」的循环都要问：突发谁吸收？
4. 高频路径不分配大块内存；
5. 短测 ≠ 稳态，报告速度前先确认采样已越过慢启动。

## 四、当前已知差距（下一轮）

| 差距 | 影响 | 方向 |
|---|---|---|
| gVisor 无 BBR（只有 CUBIC/RENO） | 高丢包长链路吞吐不及桌面 QUIC+BBR | 考虑外层换 QUIC/MASQUE，或引入带批处理的栈 |
| 外层单包 I/O（无 GSO/批处理） | 高 pps 时 CPU 占用与吞吐上限 | 参考 sing-tun 的 batch/GSO 实现 |
| 连接后 512 KB 短测偏低 | 界面数字比真实值低一个量级 | 改成"启动段/稳态"两档展示，或延长采样 |
