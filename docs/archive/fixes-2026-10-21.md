# 修复说明（2026-10-21，基线 `baseline-2026-10-21`）

四件事：赛风出口地区、误报「探测失败」、WG + 赛风慢/失败、图标上的 XEHN。

## 1. Psiphon 出口地区选择

参考 `D:\aether`（桌面版）的做法：地区列表**只用 Psiphon 自己上报的**
`AvailableEgressRegions`，内置 28 国表只是「一次都没连过」时的兜底 —— 手写大表里
有它根本不落地的国家（HK/TW/CN/RU），选中会连三分钟然后失败。

| 层 | 改动 |
|---|---|
| `engine/warp/regions.go`（新增） | `NormalizeRegion` / `RegionOffered` / `PsiphonRegions`：选择器、预检、下发三处共用一套判定 |
| `engine/warp/psiphon.go` | `PsiphonOptions.EgressRegion` → `buildPsiphonConfig` 写 `EgressRegion`；收到上报就 `SetPsiphonRegions`；**选了它不去的地区立刻失败**（`regionErr`，不等 180s） |
| `engine/warpbackend.go` | `SetPsiphonRegion`；连接前用缓存表预检并给出可选值；成功后把上报表落盘 `psiphon-regions.json` |
| `engine/engine.go` | `SetPsiphonRegion` / `PsiphonRegionsJSON`（gobind 不支持切片返回值） |
| `app/.../SettingsScreen.kt` | 设置页「出口」里新增「出口地区」：旗帜 + 中文名 + 代码，未开 Psiphon 时提示先开 |
| `app/.../AppSettings.kt` | `exitRegion` 持久化 |
| `app/.../WarpVpnService.kt` | `connect` 之前下发（`EgressRegion` 是启动参数，改不了运行中的会话） |

「自动」= 不下发 `EgressRegion`，并且把官方 config 里可能带的同名键删掉 ——
否则会出现「界面写自动、实际钉在某个国家」。

## 2. 误报「探测失败：出口已不可达」

现场日志：`已连接 … (CN)` 之后 6 秒就写「连续 3 次探测失败」，而界面延迟仍有
数值、上网正常。原因在 `engine/engine.go` 的采样器，三条都踩中：

1. 连上就开始探，没有预热 —— 隧道刚建立时探测必然失败；
2. 单次超时 3s（移动网络 + 隧道太紧）；
3. 只看「连续 3 次失败」（2s 一跳 = 6 秒），完全不看数据面是否真的在动。

现在：预热 12s、超时 5s、阈值 5 次，**并且只要 tun 还在进出字节就不计数** ——
探测包被丢（DNS/ICMP/端口被拦）不等于隧道死了。判定为断时把延迟清零显示「—」。

## 3. WG + Psiphon 慢 / 失败

现场：上游握手成功、出口验证都过了，Psiphon 起来后大量
`meek round trip failed … connection refused`，最后报「180s 内没有建立隧道」。
根因是端点「握手成功后十几秒才死」，而 Psiphon 正好栽在这段时间里。

现在加了**上游看门狗**：叠加过程中每 6s 经上游自己的 SOCKS 探一次，连续 2 次不通
就中止本次叠加并说清原因（成功路径零代价，不阻塞启动）。另外 wg 失败时补一句
「WireGuard 在这里最容易被识别，建议换成 AmneziaWG」。

没有照搬 aether 的「阻塞式稳定门」（连续 2 次探测通过才启动出口）：那会让本来就
能通的 AWG 每次多等 6 秒。看门狗是等价的止损效果，但成功路径不加延迟。

## 4. 图标上的 XEHN

`logo.png` 卡片底部印着 XEHN，而 App 名字本来就叫 `Xehn`，启动器里重复显示。
`tools/make-icons.ps1` 现在两步处理：

1. 用「逐列线性插值」擦掉那行字（背景是柔和横向波浪，看不出接缝；填纯色会留补丁）；
2. 构图裁到「字样上方 12px」，再把标志本身放大 —— 不依赖擦除是否完美，字必然在
   裁切之外，顺带解决了原来下半张空着的问题。

同时 `versionCode 2 → 3`（启动器按 包名+versionCode 缓存图标，不升版本号覆盖安装
会继续显示旧图标）。

# 第二轮（14:00）：系统 VPN 不断开 + WG 叠加重试 + 日志卡片

## 5. 失败/断开后系统 VPN 仍显示已连接

根因在 psiphon 源码里：`psiphon/common/tun/tun_unix.go` 的 `fileFromFD` 对传入的
tun fd 做了 **`unix.Dup(fd)`**，packet tunnel 用的是副本，**原 fd 一直留在我们
手上**。而上一版把 fd 记成「已被 Psiphon 接管」，于是失败路径和断开路径都不敢关
它 —— 系统 VPN 就一直挂着（`设置 → VPN` 里还是已连接），只能杀进程恢复。

现在：

- `startPsiphon` 不再 `ClaimTunFD`（Psiphon 并没有接管原 fd）；
- `Session` 新增 `tunFD`，`Close()` 里自己关（断开时 system tun 必然下线）；
- 失败路径仍由 `ReleaseTunFD` 兜底，但它现在真的会关。

## 6. WG + Psiphon 换成「换端点重试」

日志证据（`xhwarp-log-20261021-135541.txt`）：`Tunnels {"count":1}` 之后 1-2 秒
就 `DoStatusRequest failed … EOF` → `Tunnels {"count":0}` → `Exiting`，随后出口
实测当然失败。也就是说：**Psiphon 隧道建立起来了，是上游把它掐断的**。

只赌一个端点在这种网络里必然失败，所以：

- `DialPsiphon` 拆成 `dialPsiphonOnce` + 重试循环：最多 3 次、总预算 150s；
- 每次失败用 `Options.Skip` 把刚死掉的端点排除，换一个再试；
- 只重试「上游不稳」这一类（看门狗触发 / 出口实测时上游同时不通）；
  地区不提供、缺 client.config、Psiphon 侧起不来都属于硬错误，直接报；
- 单次等待就绪的上限取 `min(180s, 剩余预算)`，避免第一次就把预算耗光。

## 7. 日志卡片

- 去掉「运行日志」标题：卡片一窄它就被压成竖排四个字（运/行/日/志），
  行数说明 (`显示最近 N 行 · 共 M 行`) 自己就够；
- 「导出」改成「分享」：日志写到 `cache/logs/xhwarp-log-<时间>.txt`，经
  `FileProvider` + `ACTION_SEND` 交给系统分享面板 —— 对方收到的是真正的 txt
  附件（原来走 SAF 的 `content://` Uri，微信/QQ 这类应用不认）。

验证：`go build/vet/test` 全过；AAR 19 个绑定方法；APK 79.66 MB（debug 未混淆，
`classes.dex` 占 42 MB）、versionCode 3 / 0.2.1、manifest 内已含
`androidx.core.content.FileProvider`（authorities = `com.xiaohe.vpn.fileprovider`）。

# 第三轮（15:30）：会话内自动恢复（换端点重连）

现象（`xhwarp-log-20261021-151930.txt`）：界面「已连接 39:06」、上下行 **0 B/s**、
网页打不开。日志里**其实已经有**这一行：

```
[engine] 隧道连续 5 次探测失败且无数据流动：出口已不可达（可能被切断）
```

判定是对的，**但只写了日志，没有任何动作** —— 所以界面一直「已连接」，而实际
上一个包都出不去。这正是用户说的「没有自动切换断点吗」。

现在三层配合：

1. **引擎判定**（`engine.go` 的采样器）：连续 5 次探测失败**且**无数据流动 →
   `session.markNeedsRecover()` 把 `needRecover` 写进快照；隧道自己缓过来时
   （探测成功）自动撤销该标记，避免白断开一次。
2. **服务执行**（`WarpVpnService.startWatchdog`）：每 5 秒读一次快照，置位就
   「断开 → 重新 establish → 重连」。5 分钟内最多 3 次，超过就停手并写清原因
   （链路被整体掐断时，无限重连只会耗电、刷日志，界面还一直显示「在连」）。
3. **换端点**（`Engine.Connect` + `warpBackend.forgetEndpoint`）：检测到上一轮
   是「死亡后重连」，就把该死端点从 `last-endpoint.json` 里删掉 —— 否则新一轮
   仍会先试同一个，表现就是「一直卡在同一个断点上」。

验证：`go build/vet/test` 全过；AAR 23 个绑定方法；APK 58.34 MB（clean 构建）。
真机待验：拔掉网络/端点被掐后，日志应出现 `出口长时间无数据，自动重连（第 1 次）`
并在 ~10 秒内自己回到「已连接」，且端点与之前不同。

（debug 未混淆，`classes.dex` 占 42 MB）、versionCode 3 / 0.2.1、manifest 内已含
`androidx.core.content.FileProvider`（authorities = `com.xiaohe.vpn.fileprovider`）。
